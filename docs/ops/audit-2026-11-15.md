## 4. Config

Names only. Read at build time by `src/config.js`: `VITE_PLATFORM_URL`, `VITE_BILLING_BASE_URL`, `VITE_SHOP_DOMAIN`,
`VITE_SIGNUP_OPEN`, `VITE_HUB_URL`. `.env.production` (committed, public addresses only) sets `VITE_BILLING_BASE_URL` and
`VITE_SIGNUP_OPEN`. Nothing is "required": every name has a safe default (`config.js:4`), so a missing value cannot stop a build.

- **W7 acceptable.** `config.js:9` does `const env = import.meta.env || {}` and reads `env[key]`: Vite cannot see which names are
  used, so it inlines the whole object. In the built `index-*.js`: `{BASE_URL:'./',DEV:!1,MODE:'production',PROD:!0,SSR:!1,VITE_BILLING_BASE_URL:'https://intake.inphox.net',VITE_SIGNUP_OPEN:'1'}`.
  Any `VITE_*` variable set in the deploy project ends up in the page. Today that is two public values. `tests/headers.test.js`
  now fails if `.env.production` ever holds a name that is not `VITE_*`, or a value that is not an https address or a 0/1 switch.
- The company-provisioning release manifest does not list this repo (a static site, no container, no secrets): not applicable.

## 5. Deploy

The site is a static build served by Vercel (`vercel.json`; the README names no other target). There is no container, so "new
healthy before old stops" is the host's atomic deploy, which keeps the previous deployment available for an instant rollback in its
dashboard: **not exercised by this audit and not documented in the repo** (Chris, section "Needs Chris"). The risk is not the host,
it was the gate in front of it (W1): no workflow, no required check. This PR adds the workflow; it does not make it required.

## 6. Leaks

- Built bundle: clean (4b). No traceback or engine name can reach a visitor: the site has no server code; errors from the lead
  service are reduced to one fixed sentence (`SiteLogic.js:487`).
- **W3** fixed: a made-up reference number.
- **W4** fixed: the host sent no security header (`vercel.json` had `redirects` only). Now `X-Content-Type-Options: nosniff`,
  `X-Frame-Options: DENY` and `Content-Security-Policy: frame-ancestors 'none'` (nothing frames this site), `Referrer-Policy:
  strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()`. **Not added: a full
  Content-Security-Policy.** The site has many inline `style` attributes and loads two font hosts until #22 lands; a script/style policy
  must be tried as `Content-Security-Policy-Report-Only` on a preview deploy first. That is for Chris to schedule, after #22.
- One-time links, tokens: none exist on this site. Query strings: only `?plan=<code>` to the hub.
- `localStorage` holds the last shop name, the motion and walk-through choices and the game's best score: no personal data, no cookie.
